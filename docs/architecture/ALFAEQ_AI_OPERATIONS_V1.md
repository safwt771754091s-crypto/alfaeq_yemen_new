# Alfaeq Yemen — تشغيل ذكاء الفائق (Interactive AI Operations v1)

هذا المستند يوضح كيف يعمل «ذكاء الفائق» داخل التطبيق، وما هي الأخطاء التي أُصلحت، وكيف تُفعَّل الخدمة على الإنتاج.

## المسار المعماري

```
Flutter (AlfaeqAiService)
  -> Supabase Auth (جلسة المستخدم)
  -> ai-gateway (Edge Function، متحقق من الجلسة)
  -> مزوّد النموذج (OpenAI-compatible /v1/chat/completions)
  -> أدوات حقيقية (ai_tools) تقرأ وتكتب عبر RLS و RPC
```

- الأدوات للقراءة (`search_catalog`, `get_my_orders`, `get_my_cart`, ...) تُنفَّذ مباشرة.
- الأدوات المتغيرة (`add_to_cart`, `create_order_draft`, ...) تتطلب **تأكيداً صريحاً** عبر بوابة الصلاحيات.
- كل تنفيذ يُسجَّل في `ai_tool_audit_logs` (نجاح/فشل/مرفوض/بانتظار التأكيد).

## أسرار الخادم المطلوبة (Supabase Edge Functions)

تُضبط في إعدادات مشروع Supabase (وليست في التطبيق إطلاقاً):

| السر | الوصف |
| --- | --- |
| `AI_BASE_URL` | عنوان مزوّد متوافق مع OpenAI، مثال: `https://api.openai.com` أو عنوان Unsloth. |
| `AI_API_KEY` | مفتاح المزوّد. |
| `AI_MODEL` | اسم النموذج الافتراضي. |

تُقبل أيضاً الأسماء القديمة `UNSLOTH_BASE_URL` و`UNSLOTH_API_KEY` و`UNSLOTH_MODEL` للتوافق.

> إذا لم تُضبط هذه الأسرار تُرجع البوابة `ai_provider_not_configured` ويعرض التطبيق رسالة عربية واضحة بدل خطأ غامض.

## الأخطاء التي أُصلحت

1. **معلّق أداة غير مُجاب يفسد المحادثة:** عند إلغاء عملية معلّقة (أو إرسال رسالة جديدة قبل التأكيد) كانت رسالة `assistant` التي تحمل `tool_calls` تبقى دون نتيجة `tool` مقابلة، فيرفض المزوّد كل الطلبات التالية. أصبح الإلغاء يُسجّل نتيجة `tool` مطابقة (`cancelled_by_user`).
2. **تسريب `tool_calls` إلى الطلب التالي:** كان `sendMessage` يضيف الرسائل فوق تاريخ محادثة قديم يحتوي `tool_calls` معلّقاً. الآن يُلغى المعلّق تلقائياً قبل بدء رسالة جديدة.
3. **رسائل أخطاء غامضة:** رُبطت رموز خطأ البوابة (`ai_provider_not_configured`, `invalid_session`, `ai_provider_unreachable`) برسائل عربية إرشادية داخل `UnslothAiService`.
4. **عنوان المزوّد المكرر:** كان الرمز يبني `/v1/chat/completions` دائماً، ما ينتج `/v1/v1/chat/completions` إذا انتهى `AI_BASE_URL` بـ `/v1`. أصبح العنوان يُطبَّع.
5. **عدم رؤية ذكاء الفائق:** كان مدخل الذكاء موجوداً في صفحة `ServicesHubPage` غير القابلة للوصول. أُضيف مدخل بارز في الصفحة الرئيسية وفي تبويب «حسابي» وفي «كل الخدمات».
6. **شارة السلة ثابتة على صفر:** أصبحت شارة السلة (الرئيسية والتنقل السفلي) تقرأ العدد الحقيقي من `carts` عبر Supabase Realtime.
7. **صفحة الخدمات بلا Scaffold:** كانت `ServicesHubPage` تُرجع `ListView` بلا شريط علوي. أصبحت `Scaffold` كامل.
8. **تحذيرات `flutter analyze`:** أُصلحت 11 ملاحظة (متغيرات/استيرادات غير مستخدمة، `set literal` زائد، `catch` غير قابل للوصول).

## اختبار قبول الذكاء (AI read-only / mutation)

- قراءة: «ابحث عن ماء» -> استدعاء `search_catalog` وإرجاع بيانات حقيقية.
- تغيير: «أضف ماء للسلة» -> يظهر طلب تأكيد -> «تأكيد التنفيذ» -> يُحدَّث `carts`.
- تحقق: صف جديد في `ai_tool_audit_logs` بالنتيجة المناسبة.

## بوابة الإنتاج

قبل اعتبار الذكاء جاهزاً للإنتاج يجب وجود دليل على:

- `flutter analyze` بدون أخطاء.
- `flutter test` ناجح (يتضمن اختبار تاريخ المحادثة).
- `flutter build web --release` ناجح.
- ضبط أسرار `AI_*` ونشر `ai-gateway`.
- اختبار أداة قراءة وأداة تغيير عبر التأكيد.

## نتائج الفحص الحي (2026-10-04)

فُحص المشروع الحقيقي بحساب المالك (الدور `owner`، مستوى الوصول 100):

- **الدخول والصلاحيات:** يعملان. RLS يحمي الجداول، والمالك يرى البيانات.
- **`ai-gateway`:** منشورة وتستجيب، لكنها تُرجع `ai_gateway_not_configured` لأن أسرار `AI_*` غير مضبوطة على الخادم.
- **`developer-control` (تشغيل وكلاء OpenHands):** كان يفشل بـ `openhands_provider_not_configured` ثم `OpenHands HTTP 401 NoCredentialsError`.
  السبب: الدالة كانت تستخدم `OPENHANDS_CLOUD_API_KEY` غير الصالح ولا ترجع إلى `OPENHANDS_API_KEY` الصالح.
  أُصلح الكود ليجرّب المفتاحين ويرجع عند 401. **مطلوب على الخادم:** تصحيح `OPENHANDS_CLOUD_API_KEY` (أو إزالته) وإعادة نشر الدالة.
- **مدخل الذكاء للمالك:** أُضيفت بطاقة «ذكاء الفائق» إلى لوحة الإدارة لأن المالك لا يصل إلى `WorldHomePage`.
- **الكتالوج:** 1000 منتج `active` لكن `stock_base = 0` لكلها تقريباً (وبعض الأسعار 0.00). إدخال المخزون مقصود ألا يتم من الاستيراد؛ يجب إدخاله عبر مسار المخزون/الدفتر. `create_order` لا يمنع الطلب بسبب المخزون (يُثبّته عند 0)، لذا البيع ممكن لكن المخزون يبقى صفراً حتى يُغذّى فعلياً.

### قائمة الإجراءات على الخادم (خارج نطاق الكود)
1. ضبط `AI_BASE_URL` و`AI_API_KEY` و`AI_MODEL` ثم إعادة نشر `ai-gateway`.
2. تصحيح `OPENHANDS_CLOUD_API_KEY` (أو إزالته) ثم إعادة نشر `developer-control`.
3. تغذية المخزون والأسعار الحقيقية للمنتجات عبر مسار المخزون المعتمد.
