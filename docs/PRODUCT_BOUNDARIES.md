# فصل منصة الفائق يمن عن منصة الصفوة

## 1. الفائق يمن — المنتج التجاري

هذا المستودع مخصص حصراً لمنصة **الفائق يمن** التجارية.

المسؤوليات الحالية:
- Supabase Auth وRLS والمستخدمون والأدوار.
- الأقسام والمتاجر والمنتجات والكتالوج.
- مخزون التاجر وحجز/تحرير المخزون.
- السلة وإنشاء الطلبات وحالة الطلب.
- إدارة التاجر واعتماد المتاجر وطلبات التاجر.
- التوزيع والمندوبون وتحديث الموقع والتتبع.
- المدفوعات التجارية المتاحة فعلياً والمحافظ والسجل المالي والتسويات.
- الإشعارات وسجل التدقيق والدعم التشغيلي.
- تكاملات التشغيل اللازمة للطلبات والكتالوج، بما فيها event bus وn8n عندما تكون جزءاً من تشغيل التجارة.

## 2. ما تم فصله

لن تكون داخل تجربة الفائق يمن التجارية:
- مولد التطبيقات.
- مولد المواقع.
- مولد الخوادم وواجهات API.
- منشئ Workflows العام.
- منصة Agents العامة.
- تنفيذ مشاريع برمجية بواسطة OpenHands/Jev/Harness/Sandbox.
- بيئة التطوير الذكية العامة.

تمت إزالة واجهات الذكاء/البناء من تجربة العميل ولوحة الإدارة التجارية، وأزيلت ملفات platform/ التي كانت تصف منصة البناء من هذا المستودع.

## 3. منصة الصفوة

الاسم المستقبلي المعتمد:

**منصة الصفوة لبناء التطبيقات والخوادم والمواقع والأتمتة وأدوات الذكاء**

ستكون مشروعاً مستقلاً ومستودعاً مستقلاً، وتُبنى بعد إغلاق جاهزية الفائق يمن التجارية.

المسار المستقبلي:

طلب المستخدم → مواصفات → اختيار Agent → بيئة تنفيذ معزولة → كتابة/تعديل المشروع → Build/Test → مراجعة → Deploy → مراقبة وإصلاح

## 4. قاعدة الفصل

الفائق يمن يمكنه استخدام أتمتة تشغيلية خاصة بالتجارة (مثل أحداث الطلب والمخزون والإشعارات وn8n التشغيلي)، لكن **لا يتحول إلى منصة عامة لبناء التطبيقات والأتمتة**.

منصة الصفوة هي التي تمتلك قدرات البناء العامة.

## 5. معيار الإغلاق للفائق يمن

لن نعتبر الفائق يمن مكتملاً لمجرد نجاح Flutter. الإغلاق التجاري يتطلب تحققاً من:
1. Auth/RLS والأدوار.
2. الكتالوج والمتاجر والمنتجات.
3. المخزون والحجز والتحرير ومنع البيع الزائد.
4. السلة وإنشاء الطلب والمعاملات.
5. دورة التاجر كاملة.
6. دورة المندوب والتوزيع والتتبع.
7. الدفع/المحفظة/السجل المالي والتسويات.
8. الإشعارات والتدقيق.
9. الأتمتة التشغيلية المرتبطة بالتجارة.
10. Android/Web CI وإصدارات الإنتاج.
11. فحص Supabase الأمني والأداء.
12. اختبار E2E حقيقي قبل إعلان الجاهزية.
