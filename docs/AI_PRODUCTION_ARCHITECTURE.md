# ذكاء الفائق يمن — بنية الذكاء الإنتاجية

## الهدف

ذكاء الفائق ليس شاشة محادثة فقط. هو طبقة وكيل (AI Agent) داخل المنصة، تستخدم نموذجًا خارجيًا عبر بوابة خادمية، ثم تستدعي أدوات المنصة الحقيقية وفق صلاحيات المستخدم.

## المسار الإنتاجي

Flutter
→ Supabase Auth
→ Supabase Edge Function: `ai-gateway`
→ OpenAI-compatible inference endpoint
→ نموذج الذكاء (مثل Naive-N0.5-Flash عند توفير خادم inference مناسب)

وعند الحاجة إلى تنفيذ عملية:

AI → Tool schema → بوابة الصلاحيات → Supabase/RPC → نتيجة حقيقية → AI

أما الأتمتة الخارجية:

Supabase → `automation_events` → `automation-worker` → n8n → WhatsApp / Sheets / Image Studio / خدمات أخرى.

## لماذا لا نضع Naive-N0.5-Flash داخل Flutter؟

المستودع `Naive-N0.5-Flash` هو مستودع نموذج ذكاء، وليس تطبيق Flutter. أوزان النموذج كبيرة جدًا وتحتاج إلى خادم inference مزودًا بعتاد GPU مناسب. لذلك يبقى النموذج خارج APK/Web، بينما التطبيق يتعامل مع بوابة `ai-gateway`.

## إعداد مزود النموذج

تستخدم Edge Function المتغيرات التالية:

- `AI_BASE_URL`: عنوان خادم inference المتوافق مع `/v1/chat/completions`.
- `AI_API_KEY`: مفتاح المزود، إن كان مطلوبًا.
- `AI_MODEL`: اسم النموذج الافتراضي.

وما زالت متغيرات `UNSLOTH_BASE_URL`, `UNSLOTH_API_KEY`, `UNSLOTH_MODEL` مدعومة للتوافق مع الإعداد السابق.

**لا تضع أي مفتاح مزود داخل Flutter أو GitHub أو ملفات التطبيق.**

## مبدأ الصلاحيات

بوابة `ai_permission_gateway.dart` هي الحد الأمني لأدوات الوكيل:

- القراءة يمكن تنفيذها تلقائيًا حسب الدور.
- العمليات القابلة للتغيير تحتاج تأكيد المستخدم.
- العمليات الحساسة يجب إضافتها لاحقًا بسياسة مستقلة وتدقيق واضح.
- قاعدة البيانات وRLS تبقى مصدر الحقيقة، وليس النموذج.

## ما سنضيفه تدريجيًا

1. قراءة حقيقية للمنتجات والمتاجر والطلبات والحساب.
2. تنفيذ آمن للسلة وإنشاء مسودة طلب.
3. أدوات المالك/الإدارة للتشغيل والتحليلات بعد التحقق من الدور.
4. أدوات الأتمتة عبر `automation_events` وn8n.
5. أدوات تشغيلية للمخزون والتجار والتوصيل والمدفوعات، كل أداة بصلاحيات منفصلة.
6. ذاكرة محادثة وحالة جلسة محفوظة بطريقة لا تكشف الأسرار.
7. تسجيل تدقيق (audit) للعمليات التنفيذية.
8. إضافة Naive-N0.5-Flash أو مزود آخر كخادم inference قابل للاستبدال.

## قاعدة مهمة

النموذج لا يحصل على صلاحيات Supabase مباشرة ولا على `service_role`. النموذج يقترح استدعاء أداة فقط؛ التنفيذ الفعلي يمر عبر كود المنصة وسياسات الصلاحيات وRLS.
